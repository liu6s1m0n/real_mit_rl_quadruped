## 最直接的控制异常：后腿位置项抵消了承重前馈

时间零点是 CAN 首次偏离站立目标的 MIT 指令，epoch=1791535260.764814。
解析实际发送帧，再用发送前最近一次有效回包计算：

`tau_est = tau_ff + Kp*(q_des-q) + Kd*(dq_des-dq)`

方向已统一到模型坐标；它是主机估算，不能等同于电机内部瞬时电流/力矩。

|---|---|---|---|
| RR，右后 | 1.00417→0.85039 | +6.476 / −9.063 / 0 | +9.736→−2.587 |
| RL，左后 | 1.00417→0.85883 | +7.414 / −7.480 / +0.048 | +12.629→−0.017 |
| FR，右前 | 1.00417→1.12727 | +4.835 / +3.120 / −0.048 | −0.812→+7.907 |
| FL，左前 | 1.00417→1.08854 | +5.949 / +4.635 / +0.048 | +6.683→+10.632 |

后腿所用反馈年龄分别约 1.763 / 1.773 ms，状态仍为 Enabled。约 +16 ms
真实回包的后腿小腿力矩已经降到 +4.132 / +4.249 Nm。

初期十帧 WBC 日志均为 `contacts=4, tasks=2, success=true`；步态第一段约
50 ms 仍四脚支撑。即：后腿目标和力矩变化发生在计划摆腿之前，不能只解释为
正常抬脚收腿。这支持“后腿先卸载，后端更容易下沉”的机制，但不能据此证明
四腿全部力矩同时为零，也不能把单个关节力矩当成完整足端支撑力。

## 为什么会有这种控制冲突

站立覆盖 KinWBC 的关节目标，最终固定到 home；WBIC 前馈另乘 1.3，
关节 Kp=[85,85,100]、Kd=[1.8,1.8,1.8]。
行走采用 KinWBC 的目标，未沿用站立的前馈放大，Kp≈59.8、Kd≈4.95。
在该记录中，这些变化直接进入首批 MIT 帧。后腿位置项变化约 −9 Nm，
前馈变化约 −3 Nm，位置参考冲突是较大的因素。

KinWBC 通过接触雅可比和机身任务的位置误差生成关节修正；该位置修正不乘
控制周期。姿态估计、机械零位或接触几何不一致时，关节 PD 可能要求收腿，
同时前馈要求承重。已有几何复核推得首帧等效机身修正约 roll +4°、pitch −4.8°；
这是反算线索，旧 CSV 没有机身姿态，不能认定为真实 IMU 读数或证明安装方向错。

## 当前代码与这次实测的区别

当前 `FSM_State_Locomotion.cpp` 已有 100 ms 的目标、增益和前馈过渡，
MPC 预测步长也已与 50 ms 步态段一致。这份实测中的首帧跳变不能直接当成
当前代码仍然存在同样首帧跳变的证据；若另一轮使用最新构建，需要另一轮发帧验证。

当前仍有值得核查的控制差异：

1. 站立的机身位置增益、浮动基修正权重没有在行走构造器中对应设置；
   行走沿用 BodyPos 默认 Kp/Kd=50/1、浮动基权重 0.1，站立权重为 300。
   这影响机身任务与接触反力的优化取舍，不能解释成支撑力按 1/3000 缩小。
2. WBC 采用计划接触状态。RobotRunner 的实测接触融合只传给状态估计，
   并未反向修改 WBC 的接触集合；脚仍贴地时也可能已经被安排为摆动任务。
3. 100 ms 过渡并不等待步态；约 50 ms 已开始第一组摆腿。
   它改善首帧连续性，但不能单独保证换载完成或姿态/机械标定一致。
4. HardwareImu 使用完整启动姿态作相对零点。应核对趴卧基准、站立水平、
   IMU 安装与模型坐标是否一致；启动相对姿态接近零本身不是机械水平证明。

本次复跑当前硬件反馈路径对照测试：2/2 通过。正常模型硬件路径高度
0.315～0.325 m、峰值估算力矩 17.1 Nm；合成 +4°/−5° 姿态偏差后高度
0.305～0.325 m、峰值 25.3 Nm。该测试没有复现这次实机，也不包含供电复位。
日志：`/tmp/dm1_support_loss_current_sim.log`。

优先方向：核对站立→行走时后腿总命令是否仍抵消，及姿态/零位/接触的一致性；
同时独立核查双总线中断与设备失能。下一轮数据应同步记录计划接触、估计姿态、
最终支撑反力、实际发送的 FF/P/D、反馈年龄及电源状态，才能确定完整因果顺序。

## 算法专项复核：按要求暂不讨论通信或撞击后的失能

本节调用当前已编译的实际 OrientationEstimator、LocomotionCtrl、KinWBC、
WBIC、FloatingBaseModel 和 RobotRunner 做离线探针，未发送实机命令，
未修改生产控制代码。源码/结果分别在 `/tmp/dm1_algorithm_probe.cpp/.log`
和 `/tmp/dm1_algorithm_dynamic.cpp/.log`，两个可执行文件同名去掉后缀。

### 1. 后腿卸载机制在实际 WBC 中可复现

输入使用 16:38 切换前十二关节角、零速度、机身高度 0.325 m、目标 0.320 m，
四腿均为支撑、每腿期望反力为体重的四分之一，当前行走增益与默认权重。
姿态输入采用先前由关节目标反推的 roll −3.98°、pitch +4.802°，目标为水平。
该姿态是推断条件，并非日志中直接记录的 IMU 真值；反力输入是静态分配，
也不是完整历史 MPC 回放。

| 后腿小腿 | WBC 目标 rad | FF Nm | P Nm | FF+P Nm | WBIC 规划 Fz N |
|---|---:|---:|---:|---:|---:|
| RR | 0.85191 | +6.555 | −8.968 | −2.413 | +35.655 |
| RL | 0.86040 | +7.308 | −7.382 | −0.074 | +37.056 |

目标角与历史发帧 0.85039/0.85883 rad 相差约 0.0015 rad。
这证明在上述条件下，不需要失能就能生成“前腿仍出力、后腿力矩近零/反向”的命令。
`WBC_Ctrl.cpp:227–234` 将关节 PD 加在 WBIC 前馈之外，QP 的反力约束并不
保证最终 FF+PD 的接触力仍合理。用同模型、四足固定约束反算最终命令，后腿
需要负法向力（约 −20.8/−12.7 N）才能成立；普通地面无法提供这种向下拉力。
这些数值是模型反算，不是实测地面反力或实际跌落加速度。

站立在 `FSM_State_BalanceStand.cpp:179/229` 放大 FF 1.3 倍并用 home 覆盖
KinWBC 关节目标；行走恢复 KinWBC 姿态修正。因而站立成功不能证明姿态输入、
关节零位和行走运动学目标一致，切换会暴露原先被 home 目标掩盖的误差。

### 2. 已确认 IMU 融合的参考坐标不一致

`sensor/imu.cpp:472` 用完整启动四元数消除 roll/pitch/yaw；原始机身加速度保持不变。
`OrientationEstimator.cpp:294/312` 同时融合原始重力方向和上述相对四元数。
`PositionVelocityEstimator.cpp:302` 又假设世界重力为 (0,0,−g)。当启动姿态含
倾斜时，相对世界的重力实际上也已倾斜，三者并不一致。

使用日志真实启动重力 (−0.652,−0.659,10.055) m/s²，输入相对姿态恒等、
角速度零，500 Hz 连续静止 5 s：估计稳态 roll −0.614°、pitch +0.606°，
减重力后的伪线加速度约 (−0.545,−0.551,−0.030) m/s²。
这是独立可复现的估计算法问题；它本身不足以证明旧测试的约 5° 姿态差来源。
正确方向是统一世界坐标和重力基准，不能靠将机身原始加速度随意旋转“归零”。

### 3. WBIC 最终加速度没有继续满足支撑脚约束

`WBIC.cpp:103–110` 先保证 Jc*qdd+Jdot*qdot=0，`WBIC.cpp:151–155`
随后只修正六维浮动基加速度，没有同时修正关节加速度或重新约束支撑脚。
上述探针输出的十二维接触加速度残差范数为 7.764 m/s²，而结果仍 valid=true。
行走浮动基权重默认 0.1；站立设为 300。仅将探针权重改为 300，残差降到
0.770 m/s²，但 RR 的 FF+P 仍为 −1.417 Nm。权重调整不是后腿卸载的完整修复。

### 4. 当前 100 ms 过渡的动态验证和限制

MuJoCo 物理 + 实际硬件反馈 RobotRunner，500 Hz、每个场景进入行走后运行 4 s，
共四个场景全部完成，无 FSM 回退；这些是合成偏差敏感性实验，不是实机重放。

| 合成 IMU 姿态偏差 | 注入阶段 | 最低机身高度 m | 峰值总命令 Nm |
|---|---|---:|---:|
| 无 | 全程 | 0.315 | 17.1 |
| −4°/+5° | 切入行走后 | 0.295 | 22.5 |
| −4°/+5° | 站立及行走 | 0.296 | 22.8 |
| −5°/+6° | 站立及行走 | 0.290 | 23.4 |

当前过渡首帧保持站立目标，改善了历史首帧跳变；但步态约 50 ms 就开始摆腿，
此时过渡只完成一半，WBC 接触集合按计划切换，实测接触融合仅进入状态估计器。
上述实验仍能行走，没有复现“立即完全倒地”，不能宣称已找到唯一根因。
算法修复优先核对姿态/重力/机械零位的一致性，再处理最终力矩与接触约束一致性，
以及站立→行走的承重移交；仅去掉失能保护或继续加大增益无法消除这些问题。
