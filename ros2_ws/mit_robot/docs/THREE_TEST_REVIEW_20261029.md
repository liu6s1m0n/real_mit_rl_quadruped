# 2026-10-29 三次实机单次踏步复核

本轮确认有三次新测试。站立阶段稳定，踏步仍全部失败。保护前最明确的新问题是：
三次均出现约一个控制周期宽的前馈力矩尖峰；MPC 期望关节速度在策略更新时的跳变，
经 WBC 差分变成很大的期望关节加速度，是需要优先修复的链路。
现有数据不能证明这就是电机失能保护的唯一原因。

本轮仅分析和离线验证，没有修改生产控制代码、参数，也没有操作实机。
当前质量按配置 **14.705035 kg**、重力 **9.81 m/s²** 计算，静态支撑需求约 **144.26 N**。

## 三次共有的单周期力矩尖峰

以下直接来自保护前有效窗口中的实机记录，三个值是连续三个控制周期的前馈指令：

| 测试 | 关节 | 中间帧时间 | 前馈力矩：前一帧 → 中间帧 → 后一帧 |
| --- | --- | ---: | --- |
| 第一次 | RR calf | 11.21736 s | 14.244 → 22.218 → 14.129 Nm |
| 第二次 | RR calf | 7.80647 s | 13.849 → 24.919 → 13.893 Nm |
| 第三次 | RL calf | 7.33040 s | 16.141 → 22.115 → 15.569 Nm |

相邻帧间隔约 2.2–2.3 ms，前馈在一个周期内突增约 6–11 Nm，下一周期又回落。
这类指令脉冲确实存在，但没有故障码能将其中某一帧与电机保护直接对应。

底层速度项也会显著叠加。例如第一次峰值帧的 FL calf：
前馈 15.030 Nm、位置项 1.138 Nm、速度项 9.308 Nm，总计约 25.476 Nm。
当前更适合先处理期望速度和加速度的不连续，不能把这些结果直接解释为 KD 必须下降。

### 源码机制与离线对照

`opendog/legged_wbc/src/WbcBase.cpp` 的 `formulateBaseAccelTask()` 使用：

```cpp
jointAccel = getJointVelocities(inputDesired - inputLast_, info_) / period;
centroidalMomentumRate -= Aj * jointAccel;
```

这里差分的是**期望关节速度**，不是接触力。当前 `update()` 的模式切换注释把它描述成力计划差分，
该注释不准确。模式变化时重置 `inputLast_` 只能覆盖接触模式切换，不能覆盖同一模式内新 MPC 策略的速度跳变。
MPC 求解约 50–60 ms，而控制周期约 2.2–2.4 ms；策略更新造成的跳变被除以短控制周期后，
可产生数百 rad/s² 的加速度尖峰。
`src/control/opendog_algorithm.cpp` 当前输出混合也只由 active/planned 接触模式变化触发，
同模式内的策略更新尖峰不会触发新的混合。

用三次实测反馈分别离线回放，再固定每帧的期望状态、期望输入和实测 RBD 状态，
比较原 WBC 与仅为诊断将该差分项置零的 WBC：

| 测试 | 所选回放帧时间 | 最大期望关节加速度 | 后膝前馈：原 WBC → 诊断对照 |
| --- | ---: | ---: | ---: |
| 第一次 | 11.18264 s | 680 rad/s² | 22.53 → 14.21 Nm |
| 第二次 | 7.73242 s | 674 rad/s² | 24.38 → 14.03 Nm |
| 第三次 | 7.29303 s | 322 rad/s² | 20.06 → 16.50 Nm |

两种 WBC 在所采样的全部两腿支撑帧均返回 QP 状态 0。
第二次所选帧的 WBC 总竖直力也从 212.83 N 降至 135.60 N，说明该项会显著改变力与力矩分配。
回放 MPC 为异步计算，其脉冲时刻与实机不完全相同；该对照验证机制，不能冒充实机重现的逐帧结果。

**不能直接删掉加速度项作为修复。** 第一次回放中，删除该项后的全段 WBC 最大力矩反而从约 25.71 Nm
上升到 26.83 Nm，部分帧变化更大。真实关节加速度对应的动力学补偿仍然需要保留。
后续应让策略交接时的速度和加速度参考连续，并保持动力学关系一致，再验证尖峰是否消失。

## 后续修改优先级与数据缺口

1. 优先修复 MPC 策略更新到 WBC 的速度、加速度参考连续性，保留真实加速度补偿，验证同模式内策略更新。
